Dispatch · topology decision

Where should daemon work live in herdr?

The TUI now shows daemon tasks, but the v1 daemon still launches workers directly in worktrees. This choice determines whether those workers become navigable herdr work, and how much topology the daemon must own.

Current state

PathWhat happens today
dt go → liveCreates a herdr tab and pane immediately. The human can focus it from the TUI.
live → unattendedReuses that pane; if it vanished, internal/daemon/unattended.go recreates the task tab and runs claude --continue.
dt add → daemon queueDaemon creates a worktree and spawns a direct CLI worker. No herdr tab, pane, or persisted runtime coordinates.

Desired relationship

flowchart LR A[dt tui] --> B[SQLite task state] B --> C{daemon task} C --> D[herdr workspace] D --> E[task tab or shared tab] E --> F[agent pane] F --> G[focus from TUI]

The TUI should remain a read/focus surface. The daemon owns creation, recovery, and cleanup; SQLite stores the coordinates.

Two concrete shapes

RECOMMENDED · smallest change

One herdr tab per daemon task

Route the v1 worker through the existing EnsureWorkspace → CreateTab → RunPane path. Persist herdr_ws/tab/pane on claim/spawn. The existing TUI Enter action can focus it.

  • Matches the current v2 mental model: workspace = repo, tab = task, pane = agent.
  • Independent logs, focus, restart, and cleanup.
  • Works with current mux interface; no pane-splitting API needed.
low topology riskeasy recoverymore tabs
COMPACT BOARD

One daemon tab with one pane per task

Create one repo-level “daemon” tab, then attach each worker to a child pane. The TUI focuses the relevant pane rather than a task tab.

  • Fewer tabs and a single visual home for unattended work.
  • Requires new mux operations for split/create pane and pane lookup.
  • Pane lifecycle and cleanup become shared-resource problems.
compactnew mux APIharder recovery

Implementation boundary

ComponentChange
daemon worker spawnCreate or reuse a herdr task tab, run the selected worker CLI in its pane, and persist runtime coordinates after spawn.
worker lifecycleKeep the existing process handle and review gate as the correctness path. Herdr status is only navigation/attention state.
restart recoveryIf the task is still active and its pane is gone, recreate the tab/pane and resume or respawn according to the existing worker recovery rules.
cleanupClose the task tab when the worker is done, blocked, or the task is otherwise torn down. Never close the repo workspace.
TUIOnly needs the existing focus path, plus a clearer badge for open versus active.
